## Current service architecture

| Service | Current role |
| --- | --- |
| Supabase | Authentication, owned project data, usage/billing records and realtime-backed product data |
| Railway | Application/service hosting; workspace compute is part of the controlled WonderSpace rollout |
| Coder | Workspace control plane; customer provisioning remains gated until isolation/provisioning checks pass |
| GitHub / GHCR | Source, pull requests, CI/CodeQL and AI WONDERLAND container images |
| Stripe | Checkout and payment events for memberships and eligible one-time credit purchases |
| Cloudflare / domain | Public DNS/proxy layer for configured domains/subdomains |

## WonderSpace readiness

WonderSpace is not advertised as generally available cloud compute.

The intended Coder/Railway workspace path exists in the codebase, but customer provisioning remains behind safety, identity/isolation and cost-control gates. Until those checks pass in production, documentation and pricing must describe WonderSpace as **controlled beta / rolling access**, not guaranteed plan capacity.

## Membership and usage

AI WONDERLAND uses six customer-facing memberships:

1. Nomad
2. Creator
3. Architect
4. Studio
5. Guild
6. Enterprise

Billing is split into:

- one membership
- AI credits
- 3D credits

AI-PLAYGROUND and NPC-AI-SIM are product services, not independent subscription authorities.

## AI credits

Customer-facing AI usage is expressed as **AI credits**, not raw tokens. The legacy internal database feature key `ai_tokens` remains during migration.

AI Playground can expose the exact enabled model/provider and relative cost class. Planned builder modes are **Fast, Balanced and Advanced**, but they are not yet live selectors in every builder.

## 3D credits

GPU-heavy 3D generation/rendering uses its own monthly/purchased credit balance.

## Readiness rule

A route, integration or deployment file existing in the repository does not prove that the production dependency is enabled for every account. Docs and marketing must distinguish:

- live
- controlled beta
- configured but not enabled
- planned

This rule applies especially to billing Checkout, WonderSpace customer provisioning, provider-backed AI and managed publishing.
