## Current service architecture

| Service | Current role |
| --- | --- |
| Supabase | Authentication, owned project data, usage/billing records and realtime-backed product data |
| Railway | Application/service hosting and the per-workspace compute target for WonderSpace Coder IDEs |
| Coder | Workspace control plane and browser IDE/agent layer |
| GitHub / GHCR | Source, pull requests, CI/CodeQL and AI WONDERLAND container images |
| Stripe | Checkout and payment events for subscriptions and eligible credit purchases |
| Cloudflare / domain | Public DNS/proxy layer for dreammakerhub.website and configured product subdomains |

## WonderSpace runtime

The main IDE path uses **Coder + Railway**, not the old Kubernetes/vCluster/Envbox runtime.

Each workspace is designed to receive:

- a separate Railway project
- a Railway workspace service
- a persistent `/home/coder` volume
- the AI WONDERLAND baked development image
- code-server through the Coder agent
- an optional project-scoped Railway token when workspace project management is enabled

The baked workspace image includes Node.js 22, npm, pnpm, TypeScript, Python/pip/venv, Git, build tools, SSH, jq, ripgrep, SQLite, tmux, vim/nano, rsync, curl/wget and archive utilities. User-level package state and project files under `/home/coder` persist across workspace restarts.

## Usage and credits

AI WONDERLAND tracks billable usage across product surfaces instead of treating provider services as the product itself.

Current billing work includes:

- subscription plans
- live/metered usage
- AI token usage and token packs
- 3D/render credit usage and credit packs
- Stripe checkout/webhooks
- usage thresholds and alerts
- shared usage accounting across the main site and connected AI/3D services

## Readiness

AI WONDERLAND is under active development. A route, integration, or deployment file existing in the repository does not by itself prove that every production dependency is enabled for every user. Documentation should distinguish current architecture and implemented flows from items that still need provider credentials, deployment, account-level enablement, or final production verification.
